## sparkfit v0.6.0

Sixth release of **sparkfit**, the LLM memory capacity planner for the NVIDIA
DGX Spark (GB10). This release makes the throughput model match what people
measure on the box: MoE batched decode, a fixed per-step decode cost, prefill on
measured GB10 compute, and calibration of both decode and prefill with `doctor`.

### Highlights
- **MoE batched decode**: with B tokens per step a MoE reads about
  `E * (1 - (1 - k/E)^B)` distinct experts, not only the active parameters.
  Batched MoE throughput was overstated several-fold (gpt-oss-120b on vLLM at 64
  streams: ~2,900 tok/s aggregate before, ~260 now, ~350 output tok/s measured).
  Built-in and Hugging Face MoE models carry their expert counts; custom models
  take `--experts` and `--top-k`.
- **Fixed per-step decode overhead**: kernel launches, sampling, scheduling and
  routing are added to every step (`--step-overhead-ms`, default 4 ms), with
  `--engine` presets for vLLM, llama.cpp and ollama. Small and few-active-parameter
  MoE models were estimated up to 2x too fast; 8B+ dense models barely move.
- **Prefill on measured GB10 compute**: dense BF16 at 100 TFLOPS, FP8 2x, FP4
  3.5x, no precision speedup on engines that dequantize, and half the MFU for MoE
  grouped GEMMs. MoE prefill was overstated up to ~7x (gpt-oss-120b on llama.cpp:
  ~1,400 tok/s now, ~1,700 measured).
- **Calibrate prefill too**: `doctor --measured-ttft SECONDS` backs out the prefill
  MFU from a measured time-to-first-token, alongside `--measured-tok-s` for
  decode. A calibration saves the efficiency with the step overhead it was
  computed with, and a calibrated value is no longer replaced by an `--engine`
  preset (precedence: flag > `SPARKFIT_*` > config file > `--engine` > default).
- **Quantization auto-detect** covers the Blackwell-native 4-bit formats (MXFP4 as
  shipped by gpt-oss, NVFP4 from ModelOpt and compressed-tensors), ModelOpt and
  FBGEMM FP8, and 2-8 bit GPTQ-style configs. The built-in gpt-oss models default
  to their shipped MXFP4.
- **`serve`** honours `-b`/`-n` per model, reports per-model time-to-first-token,
  resolves quant as per-model suffix > `-q` > detected > `q4_k_m`, and accepts
  Windows paths and Hugging Face URLs.

### Commands
`plan`, `advise`, `fit`, `serve`, `cluster`, `doctor`, `scan`, `models`, plus a
one-shot quick mode (a model name, partial name, Hugging Face id, or local config
path). Every command supports `--json`.

### Install
```bash
pipx install sparkfit        # or: pip install sparkfit
sparkfit gpt-oss-120b --engine llama.cpp
```
Or clone and run the single file: `python src/sparkfit.py gpt-oss-120b`.

### Compatibility
- Python 3.10 or newer is required (3.8 and 3.9 are end-of-life).
- Decode estimates are lower than in 0.5 for MoE and small models, and prefill
  estimates are lower for MoE models: this is the model getting closer to measured
  numbers, not a regression. Re-run `doctor` if you saved a calibration with 0.5.
- Out-of-range options (including from `SPARKFIT_*` or the config file) now stop
  with a clear message instead of silently falling back to the default.
- `--experts`/`--top-k` must be given together, on a custom MoE.

### Quality
Linted with ruff, type-checked with mypy, 198 tests at about 88% coverage, CI on
Python 3.10 to 3.14, CodeQL analysis of the code and workflows, and a release
workflow that runs the checks and verifies the tag matches the package version
before publishing to PyPI.

### Notes
These are capacity-planning estimates, not measurements; cross-check with
`sparkfit scan` on the real machine and calibrate with `doctor`. Dense models at
high concurrency are still estimated optimistically, since attention and sampling
costs grow with the batch.
