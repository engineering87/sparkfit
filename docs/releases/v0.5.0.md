## sparkfit v0.5.0

Fifth release of **sparkfit**, the LLM memory capacity planner for the NVIDIA
DGX Spark (GB10). This release plans multi-node clusters, calibrates the tool to
your device, adds thermal awareness, and refreshes the model catalog.

### Highlights
- **Cluster planner**: `sparkfit cluster MODEL -N 2 ...` plans one model across
  several Spark nodes. Weights, KV-cache and activations split evenly across the
  nodes (so models too big for one box can fit), the 200 Gb/s ConnectX fabric is
  surfaced as the second bottleneck, and decode throughput scales sub-linearly
  with node count (validated at about 1.5x on two nodes). Pipeline parallelism
  (default) reports aggregate throughput; tensor parallelism reports single-stream.
- **`sparkfit doctor` and a config file**: from a measured decode tok/s, doctor
  backs out your real bandwidth efficiency and saves it to `~/.sparkfitrc`, which
  every command reads (precedence flag > environment > config > default). `--engine`
  seeds a per-engine default; with no arguments it reports the device and settings.
- **Thermal awareness in `scan`**: reports GPU temperature and warns when a
  hardware or software thermal slowdown is active, since throttling makes real
  decode run below the estimate.
- **`--engine vllm|llama.cpp|ollama`**: a per-run bandwidth-efficiency preset on
  `plan`, `advise`, `fit`, `serve`, `cluster` and the quick report.
- **Refreshed catalog**: current models added with parameters derived from the real
  Hugging Face configs: Qwen3 (8B/14B/32B, plus the MoE 30B-A3B and 235B-A22B),
  Mistral Small 24B, Phi-4, and DeepSeek-V3.

### Commands
`plan`, `advise`, `fit`, `serve`, `cluster`, `doctor`, `scan`, `models`, plus a
one-shot quick mode (a model name, partial name, Hugging Face id, or local config
path). Every command supports `--json`.

### Install
```bash
pipx install sparkfit        # or: pip install sparkfit
sparkfit llama3.1-70b
```
Or clone and run the single file: `python src/sparkfit.py llama3.1-70b`.

### Quality
Linted with ruff, type-checked with mypy, 118 tests at about 80% coverage, CI on
Python 3.8 to 3.12. Model parameters are validated against the real configs; the
multi-node and co-serving models are calibrated to published DGX Spark numbers.

### Notes
These are capacity-planning estimates, not measurements; cross-check with
`sparkfit scan` on the real machine. Multi-node throughput and the co-serving split
are estimates you can calibrate with `--scaling` / `--fabric-gbps` and `doctor`.
Gemma 3 and Llama 4 are omitted from the built-in catalog because their configs are
gated; fetch them with a Hugging Face id or a local config path.
